Accessibility

What this site aims at, what was actually done about it, what is not claimed, and how to tell me when it falls short.

The aim

This site aims at WCAG 2.1 Level AA — the Web Content Accessibility Guidelines, level AA. That is the standard I hold it to. It is not a certificate: nobody but me has audited this site, and the list below is what was actually done, not a claim that the whole of AA has been met.

What was done

What that has meant in practice. Each of these is checked automatically before the site is built, so it stays true:

  • Nothing loads from anyone else. The fonts are served from this site, and no page asks any other host for anything — no analytics, no trackers, no embedded players, no hosted fonts — so the pages work on a slow or filtered connection, and reading them tells nobody else that you were here.
  • Contrast is measured, not judged by eye. Every piece of text painted on every page is sampled in a real browser and checked against the WCAG contrast formula — 4.5 to 1 for ordinary text, 3 to 1 for large text — in the light theme and in the dark one, and in each of them reached both from your system setting and from the theme button.
  • Everything you can use, you can reach from a keyboard, and you can see where you are: every link and the theme button draws the same two-pixel ring when it takes focus.
  • The controls are big enough to hit: every link in the navigation strip, in the row of profiles and in the footer is at least 24 by 24 pixels to point at, at every width down to a 320-pixel screen. A link set inside a sentence is left at the size of the words around it.
  • Nothing moves on its own. The only motion is a short colour fade and smooth scrolling, and both are switched off for a visitor whose system asks for reduced motion.
  • The markup says what things are: one first-level heading per page, headings that never skip a level, lists marked up as lists, the navigation in a named landmark with the current page marked, and a language set on the document.
  • Every image carries a description of what it shows, written for a reader who cannot see it.
  • The site works with JavaScript switched off: the pages are ordinary links. Two things need it, and both fail quietly — the theme button, which stays hidden until the script has run rather than sitting there doing nothing, and my e-mail address, which is written as text and made into a link in your browser so that it is harder to harvest.
  • Body text is set at 16 pixels or larger, the layout reflows into one column on a phone, and no page scrolls sideways at any width down to 320 pixels.

What is not claimed

The gaps I know about, so that the list above is not read for more than it says:

  • This site has not been audited by anyone else, and it has not been tested with a screen reader, with voice control or with a magnifier. The checks above are automated ones and my own reading, and neither can tell you how a page actually sounds.
  • The CV is a PDF, and it is the weakest thing here: it is built so that its text comes out in order and every address in it is real text, but it is not a tagged PDF.
  • This is a personal site. One person writes it and keeps it working, in the time he has, so a fix may not be quick.

Reporting a problem

If something here is hard to use, or does not work with whatever you use to read the web, please tell me — that is the fastest way for it to get fixed. My address is in the footer of this page and of every other page. What helps most: which page you were on, what you were using, and what happened.
